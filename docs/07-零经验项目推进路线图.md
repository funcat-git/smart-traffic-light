# 零经验项目推进路线图

> 给"第一次完整做一个单片机项目"的小组。核心不是教你写代码，是告诉你**每一步该打开什么、点哪里、看到什么算成功、失败时先查哪里**。

---

## 零、先说清楚一件事：这个项目的真实难点在哪

你们四个人都没做过完整单片机项目。凭直觉会觉得"难点是写代码"，其实不是——代码可以让 AI 写。真正的三个难点是：

| 真实难点 | 为什么难 | 本项目怎么解决 |
|---|---|---|
| **不知道下一步做什么** | 没有经验 = 没有路线图，容易卡在原地或乱做 | 本文按周拆到动作级 |
| **不知道做对了没有** | 仿真跑起来了，但不知道显示对不对 | 每阶段设"验收关卡"，有明确判据 |
| **出错了不知道查哪** | 报错信息看不懂，改一处崩三处 | 每阶段附"排错树"，从最可能的原因查起 |

代码和电路的具体做法在 `docs/01~04`。**本文只管"怎么推进"。**

## 三、W2：搭完整电路（目标：8 个灯能按代码亮灭）

这周是把 `docs/02-Proteus搭建指南.md` 从头做一遍。

### 顺序不能乱

```
① 最小系统（W1已做）
    ↓
② 6 只信号灯 + 220Ω     ← 先做这个，最容易验证
    ↓
③ 数码管 + P0 上拉排阻   ← 最难的一步，单独做
    ↓
④ 5 个按键
    ↓
⑤ 2 只人行灯（可选，最后做）
```

**每做完一步就加载 HEX 跑一次**，不要全接完才第一次运行。全接完再跑，出问题你要查 30 根线；分步做，每步只有几根线。

### 数码管这一步单独说（90% 的人卡在这里）

四个坑，按顺序查：

| 现象 | 原因 | 解决 |
|---|---|---|
| 全黑 | **P0 没上拉** | 加 RESPACK-8，一脚接 VCC，其余接 P0.0~P0.7 |
| 显示乱码（不是数字是奇怪的段） | 共阴/共阳选错 | 本工程用**共阴**，Proteus 搜 `7SEG-MPX2-CC`（CC = Common Cathode） |
| 只亮一位，其他黑 | 位选没接 | P2.0~P2.3 分别接 4 个位的公共端 |
| 显示重影（相邻位有残影） | 没消隐 | 代码里已有（`disp_scan` 先 `SEG_PORT = SEG_OFF` 再点亮），检查是不是用了旧版代码 |

### 🚧 关卡 2 判据

- [ ] 6 只信号灯能按相位亮灭（南北绿灯时东西红灯）
- [ ] 4 位数码管能显示数字，无重影
- [ ] 按键按下数码管有变化

**过不了先查**：对照 `simulation/README.md` 的故障表，5 条覆盖 90% 情况。

## 四、W3：软硬联调（目标：完整跑完 50 秒周期）

**这周开始最需要耐心**，因为代码和电路第一次真正对接。

### 正确做法：先验证单一功能，再验证时序

```
1. 只看灯：南北绿灯是否 20 秒？
      ↓ 用手机秒表掐，不要求精确，20±1 秒就行
2. 只看数码管：倒计时是否每秒减 1？
      ↓ 要求严格，卡顿说明定时器有问题
3. 看联动：绿灯结束时，倒计时是否刚好到 0？
      ↓ 差 1 秒是正常的（先减后切），差很多是 bug
4. 看循环：跑 3 个完整周期，看是否稳定
```

### 时序不对的排错树

```
倒计时跳得快/慢
 ├─ 全部快一倍或慢一倍 → 晶振频率设错了（Proteus 里改 12MHz）
 ├─ 忽快忽慢 → 定时器初值算错，或中断里有 delay
 └─ 数码管某一位不跳 → 动态扫描位数循环有问题

倒计时正确但绿灯时长不对
 ├─ 差一点（±2秒）→ 正常，是显示逻辑的取舍
 └─ 差很多 → 检查 system.h 里的 GREEN_BASE / YEL_S / RED_S
```

### 🚧 关卡 3 判据

- [ ] 一个完整周期（50 秒）能自动跑完并循环
- [ ] 数码管读数与相位对应（绿灯开始南北 20 / 东西 25）
- [ ] 中途不卡死、不闪烁

## 五、W4：加功能（目标：5 个按键全有反应）

| 按键 | 预期现象 | 验证方法 |
|---|---|---|
| KEY_EMG（紧急） | 立即全红 8 秒 + 蜂鸣器响，然后回到正常 | 按一下，掐表 |
| KEY_NIGHT（夜间） | 4 个黄灯同时慢闪，数码管灭 | 按一下 |
| KEY_CAR_NS（南北车检） | **连按 3 次后**，下次南北绿灯变长 | 绿灯时连按，观察 |
| KEY_CAR_EW（东西车检） | 同上，作用于东西 | |
| KEY_MODE（模式） | 切定周期/感应，绿灯时长不再变化 | 切过去后绿灯固定 20 秒 |

### 按键排错树

```
按了没反应
 ├─ 全部按键都没反应 → 消抖参数太严？或按键接法错（应一端接IO一端接地，靠内部上拉）
 ├─ 只有一个没反应 → 查这一个的引脚号对不对
 └─ 按一次触发两次 → 消抖计数太小，把 key_edge 里的 >= 2 改 >= 3

按键有反应但功能不对
 ├─ 紧急模式回不来 → 检查 phase_tick 的 default 分支
 └─ 车检按了绿灯不变长 → 检查是否处在感应模式（KEY_MODE 切一下）
```

### 🚧 关卡 4 判据

- [ ] 5 个按键各按 10 次，全部正常，无卡死
- [ ] 紧急模式下蜂鸣器持续响（不是"滴"一声）
- [ ] 模式切换后绿灯时长确实变了

## 七、都靠 AI 写代码，怎么保证不出事

这是你们组的现实情况。AI 能写对 80%，但**它会犯三类错，全部靠人工把关**：

### 三类必查错误

| AI 常犯的错 | 怎么发现 | 怎么改 |
|---|---|---|
| **用了没有的引脚** | 对照 `hardware/引脚分配表.md` | 让 AI 只能改 `system.h` 里的宏 |
| **写了 `delay()` 阻塞** | 搜索 `delay` | 本项目全用定时器，出现 delay 就是错的 |
| **定时器初值算错** | 12MHz 下 2ms 应该是 `65536-2000 = 0xF830` | 对不上的就是错的 |

### 用 AI 的四步法

```
① 先给上下文：把 system.h 全文贴给它，而不是只描述"我要写个数码管"
② 让它改一个文件：不要一次让它改5个文件，改完一个编译一次
③ 立刻编译验证：不编译就继续问 = 错误累积
④ 让它解释改了哪几行：说不清楚的，说明它自己也不确定，重问
```

### 必须能自己讲出来的四件事（答辩会问）

1. 为什么不用 `delay()` → 阻塞会导致数码管停刷新、按键丢失
2. 定时器初值 `0xF830` 怎么来的 → `65536 - 2000`，2ms 中断（12MHz 下 1 机器周期 = 1μs）
3. 数码管为什么要消隐 → 段码和位选同时变化会产生重影
4. 自适应配时的两条规则 → 有车延长（+5s，上限40s）/ 无车截止（连续4s无车且已过12s）

**这四条答不上来，AI 写的代码就成了减分项。**

## 九、卡住了怎么办（三级求助）

```
第一级：自己查（10 分钟）
  ├─ simulation/README.md 的故障表
  └─ docs/02 的常见问题章节

第二级：组内问（30 分钟）
  ├─ 在群里发：现象 + 截图 + 已试过什么
  └─ 格式：「Proteus 数码管全黑，已检查P0上拉排阻接了VCC，还是黑」

第三级：问老师/AI（超出前两级）
  └─ 带上完整上下文：芯片型号、电路图截图、代码片段、报错原文
```

**别做的事**：不要"我先放着，回头再说"。单片机项目的问题会滚雪球，卡一天后面全乱。
